# 設計の明記と、今回の補足判断を区別する

元設計本文は変更していない。以下は、動くコードを構成するために必要だった補足判断・運用上の初期値であり、元から設計に明記されていたものとして扱わない。

| 項目 | 今回の扱い |
|---|---|
| 事業別モジュール化 | 今回のユーザー指示による構造変更。別サーバー化ではない。 |
| 公開環境のDB | 新規のPostgreSQLを使い、旧DBは移行元として別扱い。ローカル支援はPostgreSQL 17、ポート55432、別名volume。 |
| 技術バージョン | 提出物のSpring Boot 4.1.0 / Java 21を維持。設計指定のJUnit 5は5.13.4で管理。Framework 7のSpringExtensionはJUnit 6以上が必要なため、結合試験ではSpringExtensionを使わずSpringApplicationをJUnit5の@BeforeAllで起動する。 |
| 投稿の再送 | 任意の`Idempotency-Key` HTTPヘッダーを追加。設計のJSON項目は変えない。同一セッション・同一キー・同一内容は同じmessageIdを返す。10分経過後はこの再送保証の対象外。 |
| 投稿制限の一時保存 | 生のIPやsessionIdを保存しない。HMAC化した値を別テーブルに置き、DB行ロックで同一セッションの同時投稿を直列化する。受付記録は10分、残ったセッション行は20分経過後の定期処理で削除する。定期処理間隔は10分なので期限を過ぎても次の清掃まで行が残る場合がある。 |
| ログイン失敗制限 | 設計は回数・期間を指定していない。初期値5回/15分。環境変数で変更可能。識別にはメールアドレスのHMACを使用。初期管理者は明示設定・ランダムパスワード。 |
| 羽花の配置 | 元設計に座標式がないため、羽方向の座標帯と重複しない系列を使う。seedにイベント内の通し番号と追加時の成長帯を保存し、seedを初期値とするRandomで大きさを決める。投稿増加や一部非公開化でも既存花びらを移動させない。表示幅に応じて座標を比率変換する。 |
| 配置重複 | 5,000個のseedで座標一致がないことを検査済み。ただし「すべての花びらが一切重ならない」設計ではなく、密集時に一部が重なる。数学上異なる座標でも画面のピクセル単位で接近する場合がある。 |
| 300件の代表選択 | 公開条件を満たすmessageId昇順の先頭300件。公開総数と文字一覧のページングは別。選び方自体は元設計に指定がない。 |
| 成長表示 | 0/1/2/3/4は設計の境界。追加時の座標帯を変え、画面の段階属性・説明と完成時の羽の背景濃度を連動する。具体的な羽の形・色・アニメーション900msはデザイン数式が未定のための実装値。承認済み最終ビジュアルではない。 |
| PetalResponseの投稿日 | 要件5.4の投稿日表示のため`createdAt`を追加。詳細25の項目表にはない追加フィールドである。 |
| SNS・複数メディア | 保存テーブルと入力形式が詳細に未定なので、creator_links/media_filesを使用する。URL指定。サーバー側で遠隔URLを取得しない。 |
| スラッグ | 英小文字・数字・ハイフン、最大100文字。元設計は一意識別子の方針だけで具体的な正規表現はない。 |
| コンテンツ状態 | DRAFT/PUBLISHED/HIDDEN/ARCHIVED。元設計で全値が確定していない部分の運用値。公開表示はPUBLISHEDだけ。 |
| 管理者による作品の制作者変更 | 既存の参加関係・感想の整合性を壊さないよう、登録後の制作者の付替えは今回の編集画面では禁止。必要なら移行手順を含む別機能として設計する。 |
| クリエイター/作品への感想集計 | 表示URLのイベントに絞る。イベントをまたいだ同一人物の感想混在はさせない。 |
| 審査待ちの表示 | 投稿を保存したことを通知するが、公開用の花びら・件数には追加しない。 |
| アーカイブ | 終了日時を過ぎた公開イベントを再表示する。元設計の初期/将来記載差があるため、基本的な過去イベント閲覧を残す。VR保存や全CreVe統合表示は作らない。 |

| アクセス解析 | イベント/クリエイター/作品IDとホワイトリストの行動名のみ保存。本文や表示名は送らない。投稿保存成功はサーバーで計測。試行側が広告防止などで欠落するため、表示する完了率は観測値。 |

## 元設計内の記載差

初期のNext.js/Vercel案とJavaへの使用技術変更は区別し、後者の明示変更を反映した。DBアクセスは詳細設計のSpring Data JPAを採用した。画面IDのADM-001/ADM-006の差をコード上の新機能として解決したことにはしない。テンプレート名は詳細設計の`event-list.html`等に揃え、製品別のclasspath接頭辞を付けた。
